# Pipeline QA — 정합성 검증 체크리스트

이 프로젝트의 버그는 단계 내부가 아니라 **단계 사이 경계면**에서 발생한다. 검증은 "파일이 존재하는가"가 아니라 "양쪽이 일치하는가"를 본다. 모든 검증은 실제 스크립트 실행으로 수행한다 — 코드 리뷰만으로 PASS를 주지 않는다.

## 체크리스트 (우선순위 순)

### QA-1. 특성 파라미터 교차 비교 (차단급)
학습 특성 추출 코드와 앱 `RealtimeModelAdapter`를 **동시에 열고** 항목별 대조:

| 항목 | 학습 코드 값 | 앱 값 | 일치 |
|------|------------|-------|------|
| SR | | | |
| N_MELS | | | |
| FMIN / FMAX | | | |
| WIN_MS / HOP_MS | | | |
| 세그먼트 WIN_S | | | |
| 정규화 방식 (per-sample 표준화 여부) | | | |

하나라도 불일치 → **차단 이슈**. 모델은 에러 없이 잘못된 확률을 내므로 런타임에서 발견 불가능하다.

### QA-2. 클래스 매핑 대조 (차단급)
학습 내부 순서(알파벳순)와 앱 `UI_ORDER`(진단 표시순)는 원래 다르다 — 앱이 `thresholds.json`의 `class_names`로 이름 기반 재정렬(`reorder_local_to_ui`)을 수행한다. 따라서 검증할 것은 "순서 일치"가 아니라 **매핑 성립**이다:

1. 학습 라벨 인코딩 이름 집합 = `thresholds.json`의 `class_names` 집합 = 앱 `UI_ORDER` 집합 (3자 이름 집합 일치)
2. `thresholds.json`의 `class_names` 순서가 모델 확률 벡터 인덱스 순서와 정렬되어 있는가 (이게 틀어지면 재정렬 자체가 잘못됨)
3. 앱의 재정렬 매핑이 모든 UI_ORDER 이름에 대해 성립하는가 (누락 이름 없음)

참고: 앱 UI는 Rhonchi를 "Bronchi"로 표시한다 — 표시 라벨 매핑이 유지되는지도 확인. 매핑이 깨지면 Wheezing 확률이 Healthy로 표시되는 식의 치명적 오표시가 난다.

### QA-3. 환자 누수 검사 (차단급)
분할 산출물에서 실제로 실행:
```python
assert not (set(train_patient_ids) & set(val_patient_ids))
```
환자 ID는 파일명 접두어. 세그먼트 파일명에서 추출해 검사한다.

### QA-4. 아티팩트 end-to-end 추론
1. `scaler.pkl`, `model_lr.pkl`, `model_mlp.pkl`, `thresholds.json` 4종 로드
2. 2초 더미 오디오 → 로그멜(규약 파라미터) → scaler → 앙상블 확률
3. 확인: 확률 벡터 길이 = 클래스 수, 합 ≈ 1.0, NaN 없음
4. scaler의 기대 입력 차원과 로그멜 출력 차원 일치

### QA-5. 성능 지표 재검증
학습 리포트의 지표를 저장된 예측/모델로 재계산하여 일치 확인. 불일치 시 양쪽 값 병기.

### QA-6. 데이터 무결성 (데이터 준비 직후)
- JSON 구간이 오디오 길이 이내이고 단조 증가하는지 샘플 검사
- 세그먼트 수가 리포트 수치와 일치하는지
- 클래스 분포에 비정상적 쏠림(전처리 버그 신호)이 없는지

## 실행 원칙

- **Incremental QA**: 전체 완성 후 몰아서 하지 않는다. 데이터 준비 직후 QA-6, 학습 직후 QA-3/4/5, 배포 직전 QA-1/2/4를 실행한다. 늦게 발견된 경계면 버그는 상류 재작업 전체를 무효화한다.
- 검증 스크립트는 `_workspace/qa_scripts/`에 저장해 재실행 가능하게 남긴다.
- 결과는 `_workspace/04_qa_report.md`에 항목별 **PASS / FAIL / SKIP**으로 기록. SKIP은 사유 필수. FAIL은 재현 방법 + 담당 에이전트 명시.
- 문제를 직접 고치지 않는다. 담당 에이전트에게 전달한다.
